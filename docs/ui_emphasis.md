# 重要内容的强调标注

## 1. 目的

界面上每一处重要的内容都要带强调标注，让人一眼看到该看的东西。强调只有少才有用，所以这份规则同时规定两件事：哪些内容算重要、必须标。标注只有哪几种、别的地方不许用。

它和 `core_ideas_design.md` 3.8 节的版式规则是一套：那边说「正常的不标」，这边说「重要的必标」。

## 2. 哪些内容算重要

| 类别 | 是什么 | 例子 |
| --- | --- | --- |
| A 要你处理的事 | 等用户写决定、给许可、处理受阻的东西 | 待定的事、权限请求、受阻的负责人、升级到人类拍板的卡口 |
| B 结论 | 一段内容里要带走的那一句 | 卡片摘要里的结论、要紧的汇报、软巡检的判断、查重的结论、审稿的结论 |
| C 关键数字 | 用来判断好坏的数 | 主指标和对比的基线、硬卡口的违规数、进度、额度用量、有据和无据、数字对得上几个 |
| D 异常状态 | 和正常不一样、需要注意的状态 | 受阻、未通过、偏离、预警、改过、缺失、无据、超出预算、已过期 |
| E 用户的话 | 用户自己写下的内容，和模型写的要分得开 | 决定的原文、立项的 idea、用户建的任务、更新卡片时的附言、用户的回答 |
| F 时间节点 | 临近或已过的期限、里程碑 | 下一个里程碑、预期产出的到期日、额度的重置时间 |
| G 变化 | 上次看过之后变了的东西 | 前后对比、这一轮新增的违规、登记后改过的文件 |

不在表里的都是普通内容，不加强调：正常的状态、常规的元信息（时间、作者、路径、编号）、说明文字、导航。

## 3. 标注只有五种

| 标注 | 样子 | 用在哪 |
| --- | --- | --- |
| 重点字 | 半粗体、正文主色 | 一行里要先读到的那个词或那一句：标题、结论（B）、用户的话（E）的第一行 |
| 数字着色 | 等宽数字、半粗。中性的数用正文主色，只有好（绿）、要注意（橙）、有问题（红）才上色 | 关键数字（C）。数字旁边的说明文字用次要灰。品牌色留给链接和进行中的状态，数字不用 |
| 状态短词 | 带颜色的 2 到 4 个字，前面一个图标 | 正文和详情页里的异常状态（D）、临近或已过的时间节点（F） |
| 侧边色条 | 独占一行的条目左边一条 3 像素的色条，颜色用状态色本身 | 要你处理的事（A）用橙色，用户的话（E）用品牌色，要紧的汇报（B）用品牌色。只用在独占一行的条目上，一行文字中间的词不加色条 |
| 荧光底 | 文字下面一层很淡的底色 | 长文字里的关键句（B）、变化的部分（G）、搜索命中 |

规则：

1. 第 2 节的每一类内容，出现在任何页面上都要带上表里对应的标注。
2. 一个条目里最强的标注只有一处。一行里既有结论又有数字时，各用各的标注，不叠加。
3. 普通内容不用这五种标注，也不另造别的强调方式（整行加粗、大号字、感叹号、全大写）。列表和卡片上的标签见第 4 节。
4. 颜色从不单独表示含义，状态短词必有图标或文字。
5. 网页和 App 用同一套标注。三种界面风格和深色模式下都要清楚。

## 4. 列表和卡片上的标签

进展页的卡片和行、员工列表、顶栏这类一眼扫过的地方，状态用带底色的标签，比彩色的字好认。标签只有三种：

| 标签 | 样子 | 用在哪 |
| --- | --- | --- |
| 实底标签 | 状态色实底、白字，前面一个图标，后面的问题铺同色的淡底。等你决定的卡片描同色的边，行视图里整行铺同色的淡底 | 只用于「待你决定」。一张卡片上最多一处，是整页最强的标注 |
| 状态胶囊 | 淡底、同色的圆点和字。进行中是品牌色，完成和正常是绿，有风险和接近预算是橙，受阻、失败和超出预算是红，样例是描边的灰 | 项目状态、卡片的健康、预算状态、顶栏的待处理数和连接状态 |
| 浅底短标 | 淡底、同色的字，没有圆点 | 卡点（红）这类条目前面的类别词。硬检查和软巡检汇报里每一行末尾的结论：契合和已放行是绿，预警和告警是橙，偏离和阻断是红，待判断是灰 |

规则：

1. 健康是有风险或受阻的卡片和行，带一片同色的柔光，进度条也用同一种颜色：卡片从左上角晕开，行从左边缘晕开，不画硬边的色条。正常的不带。
2. 元信息那一行里的计数用彩色的半粗字，不加图标：等你回复的问题数是橙，失败数和未通过的硬检查数是红。
3. 带颜色的字保持状态色的色相，只调明度到读得清。橙色的字仍然是橙，不发棕。
4. 一列条目里，状态标签放在每行的末尾并靠右对齐，名称都从同一个位置开始。状态词不放在行首，长短不一的词会把后面的名称挤到不同的位置。

## 5. 页面的层次

一个页面从上往下最多三级，每一级的样子固定，靠它们把栏目分开：

| 级 | 样子 | 用在哪 |
| --- | --- | --- |
| 页面标题 | 最大的字，旁边是状态胶囊 | 项目名、页面名 |
| 栏目标题 | 横贯栏目顶部的一条标题栏：比面板深一点的底、下面一条分隔线，品牌色小方块里的图标、半粗的栏目名，右侧是属于整个栏目的说明和按钮 | 项目页的每个栏目：项目负责人、待你决定、研究回路、用量与预算、进展、实验、预期产出、仓库、记忆、对话、汇报与讲解 |
| 组内小标题 | 小一号的次要灰半粗字，没有底和线 | 栏目里的分组：待定的事、运行中、规划中、接下来 |

「待你决定」这个栏目整块描橙边，标题栏铺橙色淡底，件数是实底的橙色胶囊。别的栏目不用颜色区分。

栏目里再分出的面板（研究回路下面的硬限制质控汇报和软检测航向汇报）用小一号的同款标题栏。软巡检的每一行是：按结论着色的圆环、巡检名、行末的结论标签，下面一行是负责人的结论（正文色），还没有结论时显示问它的问题（次要灰）。

## 6. 模型写的长文字

卡片摘要、汇报、巡检说明、任务结果这类文字是模型写的，哪一句要紧只有写的人知道。规定：

- 负责人和员工在这些文字里，把结论或关键数字用 `**…**` 标出，一条最多一处。说明里写明这条。
- 界面把 `**…**` 显示成荧光底的重点字，不显示星号。没有标的照原样显示。
- 服务端不替模型猜哪句重要。

## 7. 实现

网页在一个样式文件里定义五个类：`em-key`（重点字）、`em-num`（数字着色，配 `data-tone="good|warn|bad|info"`）、`em-state`（状态短词）、`em-bar`（侧边色条，配 `data-tone`）、`em-mark`（荧光底）。各页面改用这五个类，原来零散的强调样式并进来。App 在一个文件里定义对应的五个修饰符。三种界面风格和深色模式各映射一次。带颜色的字用 `--em-green`、`--em-orange`、`--em-red`：Cloudflare 风格取 Kumo 的文字色，macOS 风格取系统色的深浅两档，纸本风格在 `oklch` 里向正文色靠拢。标签沿用原有的类：`pst`（状态胶囊）、`pc-health`（健康）、`usage-mark`（预算）、`chip`（顶栏）、`dc-line`（待你决定）。
