# 重要内容的强调标注

## 1. 目的

界面上每一处重要的内容都要带强调标注，让人一眼看到该看的东西。强调只有少才有用，所以这份规则同时规定两件事：哪些内容算重要、必须标。标注只有哪几种、别的地方不许用。

它和 `core_ideas_design.md` 3.8 节的版式规则是一套：那边说「正常的不标」，这边说「重要的必标」。

## 2. 哪些内容算重要

| 类别 | 是什么 | 例子 |
| --- | --- | --- |
| A 要你处理的事 | 等用户写决定、给许可、处理受阻的东西 | 待定的事、权限请求、受阻的负责人、升级到人类拍板的卡口 |
| B 结论 | 一段内容里要带走的那一句 | 卡片摘要里的结论、要紧的汇报、软巡检的判断、查重的结论、审稿的结论 |
| C 关键数字 | 用来判断好坏的数 | 主指标和对比的基线、硬卡口的违规数、进度、额度用量、有据和无据、数字对得上几个 |
| D 异常状态 | 和正常不一样、需要注意的状态 | 受阻、未通过、偏离、预警、改过、缺失、无据、超出预算、已过期 |
| E 用户的话 | 用户自己写下的内容，和模型写的要分得开 | 决定的原文、立项的 idea、用户建的任务、更新卡片时的附言、用户的回答 |
| F 时间节点 | 临近或已过的期限、里程碑 | 下一个里程碑、预期产出的到期日、额度的重置时间 |
| G 变化 | 上次看过之后变了的东西 | 前后对比、这一轮新增的违规、登记后改过的文件 |

不在表里的都是普通内容，不加强调：正常的状态、常规的元信息（时间、作者、路径、编号）、说明文字、导航。

## 3. 标注只有五种

| 标注 | 样子 | 用在哪 |
| --- | --- | --- |
| 重点字 | 半粗体、正文主色 | 一行里要先读到的那个词或那一句：标题、结论（B）、用户的话（E）的第一行 |
| 数字着色 | 等宽数字，颜色按含义：好是绿、要注意是橙、有问题是红、中性是品牌色 | 关键数字（C）。数字旁边的说明文字用次要灰 |
| 状态短词 | 带颜色的 2 到 4 个字，前面一个图标 | 异常状态（D）、临近或已过的时间节点（F） |
| 侧边色条 | 条目左边一条 3 像素的色条 | 要你处理的事（A）用橙色，用户的话（E）用品牌色，要紧的汇报（B）用品牌色 |
| 荧光底 | 文字下面一层很淡的底色 | 长文字里的关键句（B）、变化的部分（G）、搜索命中 |

规则：

1. 第 2 节的每一类内容，出现在任何页面上都要带上表里对应的标注。
2. 一个条目里最强的标注只有一处。一行里既有结论又有数字时，各用各的标注，不叠加。
3. 普通内容不用这五种标注，也不另造别的强调方式（整行加粗、整块底色、彩色边框、大号字、感叹号、全大写）。
4. 颜色从不单独表示含义，状态短词必有图标或文字。
5. 网页和 App 用同一套标注。三种界面风格和深色模式下都要清楚。

## 4. 模型写的长文字

卡片摘要、汇报、巡检说明、任务结果这类文字是模型写的，哪一句要紧只有写的人知道。规定：

- 负责人和员工在这些文字里，把结论或关键数字用 `**…**` 标出，一条最多一处。说明里写明这条。
- 界面把 `**…**` 显示成荧光底的重点字，不显示星号。没有标的照原样显示。
- 服务端不替模型猜哪句重要。

## 5. 实现

网页在一个样式文件里定义五个类：`em-key`（重点字）、`em-num`（数字着色，配 `data-tone="good|warn|bad|info"`）、`em-state`（状态短词）、`em-bar`（侧边色条，配 `data-tone`）、`em-mark`（荧光底）。各页面改用这五个类，原来零散的强调样式并进来。App 在一个文件里定义对应的五个修饰符。三种界面风格和深色模式各映射一次。
