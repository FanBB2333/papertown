# 相近程度怎么判断

相似度来自检索：配置了 embedding 时是向量余弦（`method = embedding`），否则是关键词覆盖率（`method = coverage`，idea 的关键词有多少比例出现在这篇论文里，按词的稀有程度加权）。

| 结论 | coverage 阈值 | embedding 阈值 | 含义 |
| --- | --- | --- | --- |
| 已被做过 | 最高 ≥ 0.85 | 最高 ≥ 0.88 | 问题、方法、场景基本都对得上 |
| 需调整 | 最高 ≥ 0.6，或 ≥ 0.5 的有 3 篇以上 | 最高 ≥ 0.78 | 有人做过相近的组合，需要换角度或缩小范围 |
| 可孵化 | 其他 | 其他 | 最相近的工作只覆盖了一部分 |

阈值由 `scripts/verdict.py` 计算，报告里的结论必须和脚本一致。

## 写"差在哪"时看三件事

1. **问题**：同一个问题，还是相邻的问题（短程 vs 长程、仿真 vs 真机）？
2. **方法**：核心机制是否相同？只是组件相同不算撞车。
3. **验证**：在什么任务、数据集上验证？没验证过的设定往往就是空白点。

关键词覆盖率高但问题不同，要在 `similar` 里说明，不要因此夸大撞车程度。
